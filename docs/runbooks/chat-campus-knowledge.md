# SmartMap campus prompt and knowledge maintenance

The instructions for how Chat responds are in `lib/ai/prompts/campus-assistant.ts`. The admin AI Knowledge screen edits searchable campus facts, not the system instructions. Its records arrive as untrusted data. Never store secrets, personal records, private prompts, or scraped page markup in an active knowledge entry.

Campus-side labels can help orientation only if a verified record supports them. Do not ingest undated housing rates, personal-looking contact numbers, unrelated outbound links, or published lists of residence hall availability. An official hostname is not an instruction or trust boundary. Verify individual facts, retain the source and review date, and avoid claiming a fresh lookup.

## Rollout and rollback

- `supabase/seed_ai_knowledge_vsu.sql` fills **missing titles** in a controlled initial seed. It does not overwrite existing rows; the normal Supabase reset only uses its configured `seed.sql`. Do not run the historical delete/reinsert seed against an existing database.
- For an existing **approved** environment, preview `supabase/patch_ai_knowledge_vsu_20261127.sql`. It rolls back by default. It only matches unique titles that retain the exact stock content, source, keywords and priority. It preserves UUIDs, keywords, priority and active state. It skips missing, duplicate, already-corrected rows or rows with edits to the guarded stock fields. An inactive flag is preserved. A skip is not permission to overwrite.
- Record the intended rows by UUID, previous and replacement content/source, and revision before applying. Quiesce concurrent editorial edits and rehearse on a disposable database. In the approved transaction, compare the returned UUIDs to the approved preview and roll back on any difference. Only an authorized operator should commit the reviewed transaction on the intended database and verify those UUIDs afterward.
- Prefer the authorized admin editor for an intentional review of a skipped row. Direct SQL does not call the app’s knowledge cache revalidation; coordinate refresh of the retrieval tag and verify eventual readback (the retrieval cache can live for about one hour). A new prompt version moves the answer cache to a new release namespace. Independently check nonproduction answers after rollout; a code or SQL test is not live validation.
- Roll back by UUID and only if current fields still match what was changed. Restore the captured previous content/source, preserve unrelated editor changes, refresh the knowledge cache, and deploy a verified new release if reverting the prompt itself.

Smoke cases: unknown room code returns no made-up pin; a Tolosa question does not silently route to Baybay; library “open now” does not assert live hours; personalized grades go to my.VSU without asking for an ID; and student schedules preserve only supported room and event details.

## Gemini default and configured fallbacks

The code fallback order is `gemini-3.5-flash-lite` then `gemini-3.1-flash-lite`. A supported explicit `GEMINI_MODEL_IDS` list preserves its order, so changing the checked-in example does not change a deployment setting. Use exact supported model IDs; set any higher-cost Flash model explicitly. `gemini-2.5-flash-lite` remains opt-in for existing providers that still have access, not the default. The older `gemini-2.5-flash` alias is normalized to `gemini-3.5-flash-lite` rather than depending on Google's December 1 redirect. The old `gemini-3.5-flash` alias is not automatically upgraded to higher-priced Flash.

Use [Google's model deprecation notice](https://aistudio.google.com/docs/deprecations), [sampling guidance](https://aistudio.google.com/docs/whats-new-gemini-3.6#sampling-parameter-deprecation), and [current pricing](https://ai.google.dev/gemini-api/docs/pricing) when changing settings. The adapter uses provider-default sampling and structured JSON. On the published standard paid text rates reviewed November 27, 2026, the new 3.5 Flash-Lite primary is $0.30 input and $2.50 output per million tokens, versus $0.25 and $1.50 for 3.1 Flash-Lite. It is not a savings over the former primary. Review actual tier and expected volume before rolling out any paid traffic. Keep model changes separate from quota purchases or deployment settings. For exact approved nonproduction smoke, verify requested and returned model IDs, structured output, and bounded calls; do not record credentials, user text or raw provider responses.
